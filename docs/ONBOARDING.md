# Onboarding a client

1. Register the client and its KB ownership.
2. Generate an API key and provision it securely to the application backend.
3. Register document sources with clear descriptions, authority rules and versioning.
4. Extract native text, review OCR where needed, and preserve headings and provenance.
5. Configure restricted source credentials and server-owned tenant permissions.
6. Register minimal parameterized database tools with documented identifiers and field semantics.
7. Define an access profile for sources, tools, fields, rows and operation budgets.
8. Validate expected answers against reviewed documents and reference database queries.
9. Test cross-client denial, revocation, live updates, ambiguities and failure behavior.
10. Enable the client only after approved access and operating requirements are satisfied.

Do not copy client records into shared model training by default. Retrieval supplies approved evidence per question. Model-provider processing and retention require their own deployment policy.

A demo that allows users to switch fictional companies is not an authentication design for real customers.
